## 发现的问题与建议（本轮未修复）

### P1：特定全局存储读取异常可造成启动白屏

复现：新上下文打开原生产构建前，将 `Storage.prototype.getItem` 设置为抛异常，同时保留 `setItem` / `removeItem` 可用。结果登录页未出现、root 无子节点，报读取异常。对照仅禁止访问 `window.localStorage` getter：登录页正常。该条件由故障注入产生，尚无真实 iPhone 复现，不代表普通私密模式必然白屏。

根因：现有 `@supabase/auth-js` 的 `lib/locks.js:22` 在模块求值阶段直接读取 `supabase.gotrue-js.locks.debug`；其 `supportsLocalStorage()` 写入探测通过后，后续读取没有捕获异常。应用主题键自己的读取保护有效，但此错误早于 React / client 初始化，AuthProvider 的 catch 无法覆盖静态导入失败。该依赖源码在各主题阶段未改动。

影响：满足条件的浏览器无法打开应用，是启动可靠性缺口；应在最终发布前决定处理或明确接受边界。最小建议：核查可审查的上游防护修复，或设计针对初始化导入的窄范围保护后单独验证。不要手改 node_modules、清空用户存储、盲目升级整套依赖，也不要只在 getClient 内加一个无效 catch。

证据：`qa/theme-stage4/production-storage-result.json`、`production-storage.mjs`；本地开发环境也稳定复现。

### P2：返回书架时档案 Sheet 保持打开

复现：390×844 进入书籍详情→打开档案 Sheet→执行浏览器 Back。路由回书架，Sheet 仍打开、焦点仍在 Sheet；重复 3/3 次。暖纸 / 夜航均存在，阶段 3B 时用 3A 原始 CSS 对照也已复现。正常关闭按钮及 ESC 可退出，没有发现数据丢失，但遮罩和焦点限制会阻碍直接操作书架。

根因：`Header.tsx` 的 `switchOpen` 独立保存；导航时 Header 保持挂载，现有 effect 只关闭搜索。`BooksWorkspace.tsx` 的 hashchange 更新页面和主区焦点，没有通知 Sheet 关闭；主题 CSS 不参与该逻辑。

最小建议：后续经批准将实际已提交导航的稳定路径传给 Header，仅路径变化时关闭 Sheet；区分导航关闭与普通关闭的焦点恢复，导航关闭移到主区并防止滚动，普通关闭仍返回档案按钮。不要引入新路由器、重写 history 或把主题作为 key。iPhone 返回手势若引起相同导航事件可能受影响，此处仅为推断，必须真机复现。

证据：`qa/theme-stage4/accessibility-result.json` 的 sheetCycles，`modals-result.json`；历史对照 `qa/theme-stage3b/baseline-back.json`。

### P2：文字放大压力下局部排版溢出 / 截断

隔离页面临时将每个元素的实际字体 / 行高加倍，四尺寸两主题检查：手机单行日期越出书籍列，与邻列接近或相交；tablet / PC 书名固定 54px 高度而放大后单行已 54px，原双行位置容不下第二行。页面总宽未溢出，正常字号通过。两主题一致，根因是冻结基线已有固定标题高度与日期不换行规则（styles.css 的 book-caption h2、compact book-date）。

这是 QA 文字压力试验，不是 iPhone 系统文字设置、浏览器缩放或完整 WCAG 认证。建议另行授权可访问性修复：标题高度用可保持默认 54px 的相对行高单位，放大条件下日期允许换行；必须再对照默认暖纸基线。本轮未改变字号 / 布局。

证据：`qa/theme-stage4/{light,dark}-text200-{390,768,1366,1920}.png`、`accessibility-result.json`。

## iPhone / 主屏幕 PWA 人工验收清单

当前没有发布本轮候选。以下清单应在另行授权、可访问的 HTTPS 候选环境执行，先记录 iPhone 型号、iOS 版本、Safari / 主屏幕模式及候选版本；桌面 WebKit 结果不能替代。

- 两种系统外观下首次访问均暖纸；选择夜航后刷新、关掉重开 Safari / 主屏幕 PWA、从后台唤醒均恢复；首屏无暖纸闪烁，系统模式变化不覆盖选择。
- 用隔离书房检查登录保持、后台回前台 / 会话续期、档案快速切换归属；搜索 / 筛选 / 排序 / 三列两列 / 长页滚动，详情返回与主题切换都保留预期状态。
- 长表单输入中文、软键盘 / 日期选择、纵向滚动、收键盘后保存 / 取消；输入 / 按钮不被遮挡，未保存草稿、同一图片预览保持。隔离保存失败 / 冲突须保留输入，不能通过正式数据制造故障。
- Dialog / Sheet 正常关闭、ESC（外接键盘）、焦点返回、危险操作默认安全项；详情打开档案 Sheet 后返回手势重点复现已知 P2。大图开关与返回不变暗或模糊。
- 刘海 / 底部 Home 区、横竖屏、Safari 工具栏收展：顶栏、Sheet、Toast、PWA 提示与大图安全区无遮挡；系统文字放大 / 页面缩放及 VoiceOver 检查局部截断、触控目标和朗读顺序。
- 夜航长书架快速滚动、菜单 / Sheet / 大图反复开关、键盘弹出时检查卡顿、掉帧、发热；封面清晰，玻璃不出现异常重绘。无法支持模糊的环境应显示可读实色。
- 候选 PWA 安装 / 冷启动：观察夜航启动画面、状态栏及底色差；不要为测试删除唯一草稿。更新提示中继续当前操作应保留输入；明确放弃并更新后只刷新一次，登录 / 档案 / 主题恢复。保存或备份进行中不得强制激活。
- 隔离书房导出 ZIP / JSON / CSV 的人工下载与打开；只在隔离空书房恢复。正式非空书房只检查恢复禁止提示，绝不执行恢复或清理原图。

静态 manifest 的 theme_color / background_color 均为 `#F4F0E8`；页面夜航 meta theme-color 仍为 `#211F1B`，实际夜航底色为 `#0B1322`。系统生成启动画面不读取用户 localStorage，可能先显示暖色再进入夜航；iOS 状态栏表现还受现有 apple 配置影响。建议暂保留默认暖纸静态启动色，真机确认可接受程度；若需要统一夜航浏览器栏，另行审查运行时 meta 配色映射。不能承诺动态 manifest 会解决 iOS 启动色，不改 SW / 图标 / 启动资源。
